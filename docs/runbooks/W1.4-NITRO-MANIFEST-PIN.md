# W1.4 Nitro reproducible measurement and pin procedure

This runbook describes the operator gate for a new Nitro EIF measurement. It
does not build an EIF, change KMS policy, deploy an enclave, or change trust
configuration.

## Build and review inputs

1. Pin the exact source commit, tracked-file manifest, Node/npm toolchain, and
   enclave build profile in the release ticket. The build must run from a
   tracked-files-only checkout.
2. On the approved Nitro build host, run the reviewed script with its
   reproducibility verification enabled:

   ```sh
   bash deploy/nitro/build-enclave-eif.sh --verify-reproducible
   ```

   The build output and PCR0/PCR1/PCR2 values are sensitive release evidence;
   store them in the approved artifact store, not in chat or shell history.
3. Review the generated manifest under `deploy/nitro/measurements/` against
   `manifest.schema.json`. Confirm the manifest binds the exact source commit,
   image digest, build inputs, and reproducibility result.
4. Run the repository gates before publication:

   ```sh
   npm run check:nitro-measurements
   npm test -- --runInBand deploy/nitro/build-eif-reproducibility.test.mjs
   ```

   A manifest that is reachable by a verifier but absent from the reviewed
   pin is a hard stop. Do not use an unverified override to make the gate pass.

## Publication and deployment order

1. Submit the manifest and verifier pin as one reviewed change. The verifier
   pin must reference the exact manifest bytes and source commit.
2. Publish the application artifact that serves the measurement endpoint and
   read it back from the deployed origin. Confirm the response contains the
   expected release identity and digest before any enclave cutover.
3. Independently compare the deployed EIF PCRs with the published manifest.
   Only the owner-approved KMS policy change may admit the new PCR set.
4. Perform a bounded drain/restart/readiness check and record the attestation
   verdict, source commit, artifact digest, and measurement manifest digest.

## Stop and rollback

- Stop on source, image, PCR, manifest, verifier-pin, or readback mismatch.
- Do not edit an existing measurement manifest in place or reuse a prior PCR
  under a new release name.
- Roll back through the approved deployment and KMS change process to the
  previously reviewed release. No direct KMS, EC2, or production action is
  authorized by this document.
