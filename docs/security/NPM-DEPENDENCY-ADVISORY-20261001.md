# npm dependency advisory remediation

## Scope

The services root lockfile was audited on 2026-10-01 with the repository's
production dependency scope (`npm audit --audit-level=high --omit=dev`). The
baseline contained two high-severity vulnerable package families:

| Package           | Vulnerable range               | Locked paths                                               | Remediation floor                          |
| ----------------- | ------------------------------ | ---------------------------------------------------------- | ------------------------------------------ |
| `brace-expansion` | `<1.1.21` or `>=4.0.0 <5.0.12` | root, `apps/web`, and the TypeScript ESLint nested closure | `1.1.21` for major 1; `5.0.12` for major 5 |
| `undici`          | `8.0.0 - 8.10.1`               | root worker runtime closure                                | `8.10.2` or newer                          |

The lockfile remediation selects `brace-expansion` 1.1.21 and 5.0.12 and
`undici` 8.11.2. The fix is lockfile-only because the vulnerable packages are
transitive and the package manifests already accept the patched versions.

## Acceptance evidence

The change is accepted only when all of the following are recorded against the
same tree:

1. `npm audit --audit-level=high --omit=dev` returns zero vulnerabilities.
2. `scripts/dependency-security.test.mjs` rejects the baseline lock and accepts
   the patched lock, including a reverse-patch mutation check.
3. The lockfile is regenerated with Node 24 and npm 10.9.2, as declared by the
   repository manifest.
4. The affected local CI jobs complete from a clean export, including the
   lockfile drift guard and the existing service test suites.
5. An independent reviewer gives GO for the exact immutable tree before an
   origin-only push.

This remediation does not close the separate Rust `rsa` advisory or the legacy
Go helper lifecycle issue; those remain tracked owner and enclave decisions.

## Current continuation evidence

This continuation validated the candidate from canonical `origin/main` at
`bb99c2d624cd9422e836ce7241dd085a1262063c` plus the current uncommitted
services fixes. The lockfile was regenerated with `npm@10.9.2` using
`npm install --package-lock-only --ignore-scripts`; the resulting diff contains
only the four patched package paths above. The host's default npm is 11.15.0,
so the pinned npm invocation is recorded explicitly rather than inferred.

- `node --test scripts/dependency-security.test.mjs`: 8/8 passed.
- `npm audit --package-lock-only --audit-level=high --omit=dev`: 0 findings.
- The complete `scripts/*.test.mjs` matrix passed 400/400 when the existing
  NeoDID pin checkout and the read-only main MiniGame checkout were supplied.
- The affected Node CI checks passed: catalog parity, web consistency, format,
  lint, module imports, gitignore protections, migration/topology gates,
  Cargo lock provenance, Rust security dependency checks, NeoDID vendor pin,
  network identity projections/consumers, release gating, and Rust vectors.
- Rust validation passed for the core, compute, and enclave-host packages:
  core tests and all integrations, 343 compute unit tests plus its integration
  suites, 314 enclave-host tests, and clippy with `-D warnings`.
- The formatter mutation test failed as designed, and the release benchmark
  over 50,000 deterministic values measured 4.07 ms for the ECMAScript
  formatter versus 33.45 ms for the former formatter.
- A deterministic 20,000-value corpus generated by the Rust formatter matched
  Node/V8 `String(number)` for both signs with zero mismatches.
- Radix parsing now strips leading zeroes, rejects no valid finite values, and
  refuses to construct a BigUint above 1024 bits; a 100,000-zero prefix and a
  1,201-bit overflow case are covered by tests. Mutating the bound caused the
  finite `0x1f` regression test to fail.
- `cargo audit` was run against the local RustSec database. It reports the
  known `RUSTSEC-2023-0071` `rsa 0.9.10` Marvin timing advisory with no fixed
  upstream release, plus the existing unmaintained `paste` and `serde_cbor`
  warnings; this remains an explicit open owner/security decision and is not
  hidden by the npm remediation.

The validation was local and isolated. It did not publish packages, alter
production services, rebuild an enclave, or change the Rust advisory status.
